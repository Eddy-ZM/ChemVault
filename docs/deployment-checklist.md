# ChemVault Deployment Checklist

Use this checklist before promoting the commercial MVP to staging or production.

Detailed staging and preview deployment steps are in `docs/staging-deployment.md`.

Cloudflare dashboard essentials:

- Build command: `npm run build`.
- Build output directory: `dist`.
- Functions directory: `functions/`.
- Preview/Staging D1 binding: `DB` -> `chemvault-staging`.
- Production D1 binding: `DB` -> `chemvault-production`.
- Do not reuse a production D1 database id for Preview/Staging.

## Local Verification

- `npm run build` passes.
- `node --test tests/*.test.mjs` passes.
- `node --check scripts/commercial-config.js` passes.
- `node --check scripts/commercial-ui.js` passes.
- `node --check scripts/site-shell.js` passes.
- `node --check "functions/api/[[path]].js"` passes.
- `sitemap.xml` and `data/public-record-index.json` are regenerated by the build.

Local preview:

```powershell
npm run build
npx wrangler pages dev dist --d1 DB=chemvault --port 8788
```

Open `http://127.0.0.1:8788`.

Stop the currently running local preview if needed:

```powershell
Stop-Process -Id 55464 -ErrorAction SilentlyContinue
```

## Cloudflare Pages Environment

Recommended Preview/Staging variables:

- `ENVIRONMENT=staging`
- `COMMERCIAL_MODE=staging`
- `ENABLE_MOCK_BILLING=true`
- `ENABLE_MOCK_AUTH=true`
- `DEFAULT_USER_PLAN=free`
- `PAYMENT_PROVIDER=`
- `PUBLIC_APP_URL=<Cloudflare Preview URL>`

Recommended Production variables:

- `ENVIRONMENT=production`
- `COMMERCIAL_MODE=production`
- `ENABLE_MOCK_BILLING=false`
- `ENABLE_MOCK_AUTH=false`
- `DEFAULT_USER_PLAN=free`
- `PAYMENT_PROVIDER=`
- `PUBLIC_APP_URL=https://chemvault.science`

- Configure `ENVIRONMENT=staging` and `COMMERCIAL_MODE=staging` for staging/preview.
- Configure `ENVIRONMENT=production` and `COMMERCIAL_MODE=production` for production.
- Set `ENABLE_MOCK_BILLING=false` in production.
- Set `ENABLE_MOCK_AUTH=false` in production.
- Do not set `DEFAULT_USER_PLAN` above `free` in production; production ignores it for entitlement elevation.
- Configure `PUBLIC_APP_URL` for the target environment.
- Keep payment secrets only in Cloudflare environment variables/secrets.
- Do not expose `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, provider customer IDs or subscription IDs in frontend code.

## D1 Environments

The Pages Function expects a D1 binding named `DB`.

Recommended databases:

- `chemvault-dev`
- `chemvault-staging`
- `chemvault-production`

Local schema:

```powershell
npx wrangler d1 execute chemvault-dev --local --file=schema.sql
```

Staging schema:

```powershell
npx wrangler d1 execute chemvault-staging --remote --file=schema.sql
```

Production schema:

```powershell
npx wrangler d1 execute chemvault-production --remote --file=schema.sql
```

- Use a separate staging D1 database and bind it as `DB` in the Cloudflare Pages Preview/Staging environment.
- Use a separate production D1 database and bind it as `DB` in the Cloudflare Pages Production environment.
- Never bind Preview/Staging directly to the production D1 database.
- Apply `schema.sql` before testing `/api/leads`.
- `schema.sql` is currently the initialization path for staging D1. Before formal production launch, migrate ongoing schema changes to Cloudflare D1 migrations.
- `subscriptions` is only a placeholder schema until real checkout/webhooks are implemented.
- `usage_records` is only a quota placeholder until real usage tracking is implemented.

## API Smoke Checks

- `GET /api/health` returns `ok: true`.
- `GET /api/entitlements` returns plan, feature map and auth mode.
- `POST /api/leads` accepts a valid lead and rejects an invalid email.
- `POST /api/billing/checkout` returns a clearly labeled placeholder in local/staging when mock billing is enabled.
- `POST /api/billing/checkout` returns `payment_not_configured` or `payment_provider_not_implemented` in production until real payment is wired.
- `POST /api/billing/portal` follows the same placeholder/not-configured rule.
- `POST /api/export/compound` returns HTTP 402 for Free/default users.

Manual API targets after Preview deployment:

- `GET <preview-url>/api/health`
- `GET <preview-url>/api/entitlements`
- `POST <preview-url>/api/leads`
- `POST <preview-url>/api/billing/checkout`
- `POST <preview-url>/api/billing/portal`
- `POST <preview-url>/api/export/compound`

## Production Blockers

Do not present the platform as having live paid access until these are implemented:

- Real auth/session.
- Real subscription state.
- Real payment checkout, webhook handling and billing portal.
- Real file library backend.
- Real molecular modeling backend.
- Real mail backend.
- Real AI paper search backend.
